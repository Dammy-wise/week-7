# Submission checklist — Weeks 1–9

Each week has a dedicated folder. Before submission, add the evidence that can only come from your own environment (IDE screenshots, actual test run, commits/tags, reviewer comments and AI interaction records).

| Week | Required submission | Included in this package |
|---|---|---|
| 01 | One GitHub repository; pricing/tax calculator; README; tests; independent solution evidence | Core Java pricing calculator, sample input/output, tests and design notes |
| 02 | Six or more domain classes/records/enums; UML; validation; README; tests | Domain model, Mermaid UML, design notes and model validation tests |
| 03 | Refactored app; two interfaces with implementations; package diagram; review checklist/comments | Ports/interfaces, layered package structure, refactoring notes and review template |
| 04 | Analyzer; sample data; List/Set/Map; reusable generic method; search/filter/sort/group/summary; tests | Dataset, analyzer source, collection notes and boundary tests |
| 05 | Three custom exceptions; safe logging; try-with-resources; at least 15 tests; defect report | Exception hierarchy, logging config, file resource example, test suite and defect-report template |
| 06 | Configurable CSV importer; JSON report; >=20 CSV records; rejected-record report; >=10 tests | 25-row sample CSV, importer/exporter implementation, config template, JSON example and tests |
| 07 | ER model; schema/constraints; sample data; CRUD SQL; normalization and AI SQL verification notes | PostgreSQL DDL, seed data, CRUD/report queries, ER diagram and verification checklist |
| 08 | Complete REST API contract; >=12 endpoints; success/error examples; Postman/Insomnia collection; API design record | OpenAPI YAML, endpoint inventory, request/response examples, Postman collection and decision record |
| 09 | Working Spring Boot app; >=8 endpoints; layers/DTOs/validation; DB integration; >=8 tests; Postman; README; AI log | Runnable Spring Boot application, H2 default/PostgreSQL profile, tests, API collection, setup and AI log template |

## Evidence still to be completed by learner
- [ ] Create a Git repository and make incremental commits; tag each milestone `week-01` … `week-09`.
- [ ] Capture actual test output and IDE debugger/breakpoint screenshots.
- [ ] Obtain and include genuine pull-request reviewer comments and corrections (Weeks 3 and 9).
- [ ] Complete the AI usage log with actual prompts, suggestions accepted/rejected, independent checks and sources. The curriculum forbids AI assistance for Weeks 1–7; comply with the instructor's policy and do not claim AI-generated work as independent work.
- [ ] Add a live service URL only after deployment; do not invent one.
